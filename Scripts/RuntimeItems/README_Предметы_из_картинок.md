# Предметы из картинок (ItemsInbox)

Система позволяет добавлять предметы в игру **без Unity и без редактора**: художник кладёт
PNG-файл в папку `ItemsInbox`, а игра сама делает из него полноценный предмет — иконку в
инвентаре, спрайт на земле, запись в `ItemDatabase`, участие в сохранениях.

Всё работает в билде (Windows Build), в редакторе Unity — так же.

---

## Как это выглядит для художника

1. Рядом с `.exe` лежит папка `ItemsInbox` (создаётся при первом запуске игры).
2. Внутрь кладётся `Красный цветок.png` (можно `.jpg`).
3. Через 1–2 секунды (или после перезапуска игры) появляется предмет:
   * название — «Красный цветок»;
   * `id` — `krasnyy_tsvetok` (транслит имени файла, стабильный для сохранений);
   * иконка в инвентаре + спрайт в мире.
4. В игре нажать **F1** → окно DevTools → вкладка «Предметы»:
   * выдать предмет в инвентарь (`+1`, `+10`);
   * поставить предмет в мир («В мир»);
   * «Пересканировать» — после правок картинки;
   * «Открыть папку» — открыть `ItemsInbox` в проводнике.

Необязательный файл настроек — `.json` с тем же именем, что и картинка
(`Красный цветок.json`). Полный список полей описан в файле
`КАК ДОБАВИТЬ ПРЕДМЕТ.txt`, который игра сама кладёт в папку предметов.

**Ограничение размера картинки:** не больше **512×512 px** по каждой стороне
(`RuntimeItemFolder.MaxIconSide`). Файлы крупнее игра не загружает — иконка и спрайт
не создаются, предмет не появляется в игре, а в DevTools («Ошибки папки» и строка
предмета) пишется фактический размер файла. Иначе огромная картинка даёт иконку,
которая не влезает в слот инвентаря.

## Как это работает внутри

```
Assets/Scripts/RuntimeItems/
├── RuntimeItemNaming.cs      — транслит, slug-id, имя предмета из имени файла
├── RuntimeItemDefinition.cs  — DTO для .json рядом с картинкой
├── RuntimeItemFolder.cs      — поиск картинок, PNG → Sprite → ItemSO, кеш и ошибки
├── RuntimeItemVisuals.cs     — создание «префабов» UI и World прямо в рантайме
├── RuntimeItemLoader.cs      — автозапуск, опрос папки, регистрация в ItemDatabase
├── RuntimeLogBuffer.cs       — накопитель логов для внутриигрового окна
└── InGameDevTools.cs         — внутриигровое окно DevTools (IMGUI, F1)
```

Порядок работы:

1. `RuntimeItemLoader` создаётся сам при старте игры
   (`[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]`) — в сценах ничего добавлять не нужно.
2. `RuntimeItemFolder.Scan` находит картинки в папках-кандидатах, читает их через
   `File.ReadAllBytes` + `Texture2D.LoadImage`, создаёт `Sprite` и
   `ScriptableObject.CreateInstance<ItemSO>()`.
3. `RuntimeItemVisuals` собирает два объекта-шаблона:
   * `*_UI` — `RectTransform 100×100` со `scale = 0.2` + `InventoryItemMarker` + дочерний
     `Image` с иконкой размером ровно в пикселях картинки (один в один как в
     `NullUIItem.prefab` и в обычных предметах из `Resources/Items/Inventory`);
   * `*_World` — `SpriteRenderer` (спрайт 100 ppu, корень `scale 0.2`) + `BoxCollider2D`
     (trigger, размер = размеру картинки / 100) + `PickupItem` — как в `NullWorldItem.prefab`;
   Шаблоны висят на **выключенном** объекте `[RuntimeItemTemplates]` (DontDestroyOnLoad),
   поэтому в сцене их не видно, а `Instantiate` даёт активную копию — как обычный префаб.
4. Они присваиваются в `ItemSO.uiPrefab` / `ItemSO.worldPrefab`, поэтому весь существующий
   код инвентаря, крафта, выбрасывания и сохранений работает без изменений.
5. `ItemDatabase.RegisterRuntimeItem` добавляет предмет в индексы по `id` и имени.
6. Раз в 1.5 секунды папка опрашивается (имя + размер + дата изменения файлов). Если файл
   добавили/перерисовали — предмет обновляется на ходу (иконки в открытом инвентаре тоже
   обновляются через `RefreshLiveInstances`).

### Где ищется папка

Проверяются (в порядке приоритета, сканируются все существующие):

1. рядом с `.exe` — в редакторе это корень проекта (там, где `Assets`);
2. `<игра>_Data/ItemsInbox`;
3. `Application.persistentDataPath/ItemsInbox`;
4. `StreamingAssets/ItemsInbox`.

Если ни одной нет — создаётся первая, вместе с инструкцией для художника.

### Идентификаторы

`id` = транслит имени файла: `Красный цветок.png` → `krasnyy_tsvetok`.
Это важно: `id` попадает в сохранения. Переименование файла = новый предмет.
При совпадении имён в разных подпапках добавляется суффикс `_2`, `_3`, …

### Категория по подпапке

Если картинка лежит в подпапке с именем категории, категория подставится автоматически:

```
ItemsInbox/Ingredient/Красный цветок.png   -> category = Ingredient
```

Допустимые имена: `None, Ingredient, Consumable, Weapon, Armor, Accessory, Tool, Quest, Currency, Misc`.

## Внутриигровое окно DevTools (F1)

Аналог редакторного `Tools/DevTools`, но в билде. Сделано на IMGUI, поэтому не зависит от
Canvas/TMP/шрифтов проекта и переживает смену сцен.

| Вкладка | Что умеет |
|---|---|
| Предметы | список предметов из папки и из `Resources`, выдача, спавн в мир, пересборка папки и базы, поиск; всё, что поставлено в мир кнопкой «В мир», попадает в список «Заспавнено из DevTools» и удаляется одной кнопкой (или по одному) |
| Логи | те же фильтры по модулям, что в редакторном DevTools, «только ошибки/предупреждения», поиск, автоскролл, экспорт в файл; размер шрифта списка (кнопки `A−`/`A+` или ползунок 8–22 px) и переключатель «Разноцветные» — все строки одним цветом; обе настройки запоминаются в `PlayerPrefs` |
| Мир | телепорт по локациям через `SceneSlideTransition` |
| Прогресс | завершение/отмена активных квестов, просмотр и переключение флагов, добавление флага |
| Инфо | пути папок, версия Unity, сцена, ошибки папки, переключатель verbose-логов |

Пока окно открыто, оно перекрывает игровой ввод: невидимая картинка на Canvas с
`sortingOrder = 32760` блокирует uGUI, а статический флаг `InGameDevTools.BlocksGameplayInput`
отключает игровые хоткеи и клики по миру/диалогу.

## Что изменено в существующем коде

Изменения минимальные и аддитивные:

| Файл | Что добавлено |
|---|---|
| `Scripts/Inventory/ItemDatabase.cs` | поле `includeRuntimeItems`, метод `RegisterRuntimeItem`, `HasItem`; `LoadDatabase` подмешивает runtime-предметы |
| `Scripts/Inventory/PickupItem.cs` | одна строка в `IsBlockedByUI` — не подбирать предметы сквозь окно DevTools |
| `Scripts/Settings/InputManager.cs` | ранний выход из `Update`, пока открыто окно DevTools |
| `Scripts/RadialMenu/RadialMenuOpener.cs` | ПКМ не открывает радиальное меню сквозь окно DevTools |
| `Scripts/RadialMenu/RadialMenu.cs` | **фикс бага:** действие контекстного меню («Выбросить») больше не пробрасывается в `RadialMenuActionHandler`, где `Exit` = `QuitGame`. Раньше игра закрывалась при выбрасывании любого предмета из инвентаря |
| `Scripts/RadialMenu/RadialMenuController.cs` | предмет без `worldPrefab` больше не удаляется из инвентаря молча + лог о выбрасывании |
| `Scripts/Dialogue/TextBeginner.cs` | клик по окну DevTools не листает диалог |
| `Editor/RuntimeItemsMenu.cs` | пункты меню `Tools → Предметы из картинок` (открыть папку / показать пути) |
| `Editor/ItemSOEditor.cs` | **фикс:** «Быстрое создание префабов» больше не нормализует иконку под 64 px (получалось 12.8 px на экране). Теперь `Image` = размер картинки в пикселях, как у существующих префабов и как в runtime-пайплайне |
| `Editor/Tests/RuntimeItemTests.cs` | EditMode-тесты на транслит, разбор json и регистрацию в базе |

Если система не нужна — достаточно удалить папку `Scripts/RuntimeItems`: останется только
поле `includeRuntimeItems` (пустой список) и четыре guard-строки, которые ничего не делают.

## Ограничения и как с ними жить

* **`id` завязан на имя файла.** Переименовали файл — для сохранений это другой предмет.
* **Размер иконки в UI = размер картинки × 0.2**, **размер в мире = размер картинки / 100 × 0.2**
  — ровно те же схемы, что у обычных предметов (`NullUIItem`: корень 100×100, `scale 0.2`,
  `Image` нативного размера; `NullWorldItem`: спрайт 100 ppu, корень `scale 0.2`,
  коллайдер нативного размера). Поэтому при одинаковой картинке предмет выглядит одинаково
  и в инвентаре, и на земле. Зелье 206×341 → иконка 41×68 и коллайдер 0.41×0.68 юнита.
  Если нужно принудительно изменить размеры — в `.json` есть `uiSize` (пиксели экрана)
  и `worldSize` (юниты, по большей стороне).
* **Уже выданные предметы** после перерисовки PNG обновляют иконку, но не пересоздаются
  в дочерних окнах (ItemViewPanel показывает новую, т.к. берёт `ItemSO.icon`).
* **Удалённый PNG** не удаляет предмет из базы — сохранения продолжают работать, в DevTools
  предмет помечается как «файл удалён».
* **Предметы из папки не являются ассетами.** Они живут только в рантайме. Если предмет
  нужно сделать «настоящим» (рецепт крафта, событие, ссылка из инспектора) — создайте его
  через `ItemSO` + «Быстрое создание префабов» в `ItemSOEditor` и положите PNG как Sprite.
* **Кодировка PNG/JPG** — стандартная, альфа-канал поддерживается.

## Быстрая проверка

1. Запустить игру (или Play Mode) — рядом с `.exe` / в корне проекта появится `ItemsInbox`.
2. Положить туда любой PNG.
3. Подождать 1–2 секунды, нажать F1 → «Предметы» → предмет в списке → `+1`.
4. Открыть инвентарь (I) — предмет с иконкой на месте.
5. «В мир» — предмет появляется в центре экрана, его можно подобрать и выбросить (сохранение
   переживёт перезапуск, пока PNG лежит в папке).
